# 作物遗传层（sjbio）

目标：给 IU 的作物加一层**双倍体遗传**——IU 的 19 条基因轴照旧，交配规则换成 IC&C 那套
（显性/隐性两个等位基因、双隐性保底升档、隐性最多比显性高 2 档），并且规则可读、有上限。

## 1. 分层：显性用 IU 的组件，隐性另存一份

| 层 | 存放位置 | 谁在读 |
| --- | --- | --- |
| 显性 | IU 自己的 `GENOME_CROP` 组件（`GenomeCrop`） | IU 的生长逻辑、作物架、分析仪 |
| 隐性 | 本模组的 `sinkjourneycore:crop_alleles` 组件 | 只有本模组的交配与分析 |

IU 的 `Genome.writeNBT` 就是 `stack.set(GENOME_CROP, new GenomeCrop(map))`，只替换自己那一个组件，
所以两个组件挂同一个物品上互不覆盖。这对我们很关键：**显性层零侵入**，IU 一行不用改，
它的产量、抗性、生长判断全部照旧读 `GENOME_CROP`。

没有隐性记录的物品（老存档、IU 自己产出的种子）一律按「显 = 隐」回填。

## 2. 轴的分类

19 条轴从 `GeneticTraits` 的枚举名推出来（`SOIL_II` → 土壤 2 档），不写死档位表。
其中 6 条是**类别轴**，档位是并列选项而不是高低：

- `BIOME`：地狱/温暖/温和/寒冷/积雪
- `WATER`、`BEE`、`SOIL_BLOCK`、`SUN`、`NIGHT_GROW`：单值开关

类别轴只做继承、不升档——把生物群系当阶梯算会得出无意义的「+1」。
其余 13 条（产量、收获概率、种子、生长速度、土壤、光照、空气、天气、虫害、杂草、辐射、
遗传抗性、适应性）是阶梯轴，走 IC&C 的升档规则。

## 3. 交配规则（`AlleleMath`）

```
从父母各取一个等位基因（取显/取隐各 50%）
显性档 = max(双亲显性, 被选中的两个里较小的)
隐性档 = max(显性, 被选中的两个里较大的)，且 <= 显性 + 2
两个都取自隐性时：显性档至少 = 好亲本显性 + 1（封顶），再随机 +0~1
```

IC&C 把上限写死成六档品质，这里把 cap 参数化成每条轴自己的档数。
`AlleleMath` 是纯整数运算、不碰 Minecraft，所以可以脱离游戏验证（`tools/allele-check.sh`）。

## 4. 命令

| 命令 | 作用 |
| --- | --- |
| `/sjbio inspect` | 打印手上作物 19 轴的 显性/隐性/上限，按产量/环境/抗性分组，并给出总档位 |
| `/sjbio writetest` | 隐性层读写往返测试：写入贴住上限的隐性层、读回比对、再还原；同时验证显性层没被覆盖 |
| `/sjbio cross` | 把手上作物与自身交配一次（只打印不写回），看规则跑起来什么样 |

## 5. 还没做的（下一步）

1. **接进掉落路径**：在 `TileEntityCrop.getSelfDrops(int, boolean)` 返回处接管，用
   `SJBiology.cross` 的结果覆盖 IU 自己 `addGenome(...)` 的随机结果——单一写入点。
   多方块作物架（`BlockEntityMultiCrop`）是否走同一条路径尚未确认。
2. **预算裁剪**：19 轴全满约 49 档（显性侧），预算设 24~32 档，按 `Group.trimPriority`
   先砍抗性、再砍环境、最后砍产量，并显示给玩家。
3. **代数门槛**：高档位要求 `ICrop.getGeneration()` 达到阈值。
4. **分析仪界面**：独立方块，分组显示，比给 IU 的界面打补丁稳。
5. **蜂授粉回填**：`isBeeCombine` 那条路径会直接改 `GENOME_CROP`，绕过隐性层，需要兜底。

  合计 49 档。
